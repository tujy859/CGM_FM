四、修复的阻断问题（共 5 项）

1. TS2Vec 子模块钉死 commit 已从上游消失

models/ts2vec 子模块指向的 commit 5cde9ce 在上游仓库已不可拉取（git 报 "not our ref"）。改为克隆上游 HEAD（b0088e1，2023-06 最终版），并将 ts2vec.py 顶部的绝对导入（from models import ... 等 3 行）改为相对导入，避免与宿主仓库自身的 models/ 包冲突。改后 checkpoint Output/baselines/ts2vec.pkl 加载验证通过。

2. GluFormer 评估崩溃：词表不匹配导致嵌入索引越界

TokenDataTransformer 硬编码 280 个血糖分箱，而发布权重（v5）的 vocab_size 为 278，home CGM 均值序列分箱后出现 token=279 越界（IndexError: index out of range）。修复：num_bins 参数化并贯通三层 —— data_loaders/data_transformer.py（从 config 读取 num_bins，缺省仍 280）、data_loaders/base_loader/base_loader.py（update_transformer 透传）、config/model_configs.py（GluFormer 探针注入 num_bins=vocab_size）。与 eval/class_reg.py 中按 encoder 自适应词表的既有逻辑口径一致。

3. Mantis / MOMENT 在线拉取权重网络抖动

评估过程中在线 from_pretrained 频繁超时/SSL 中断。改为评估前用 huggingface-cli download（带重试）预下载三个模型到 HF 缓存，随后以 HF_HUB_OFFLINE=1 + TRANSFORMERS_OFFLINE=1 离线运行全量评估，不再受网络影响。

4. wandb 未登录导致每格评估以 exit 1 结束

config/config_downstream.py 默认 enable_wandb: True，每格评估在结尾 wandb.init 处因无 API key 崩溃（指标已全部算完但进程报失败）。按 STRATEGY.md「eval 不需要 wandb」将其改为 False。

5. 脚本方式运行时找不到项目根包

python scripts/run_all_eval.py 以文件方式启动时项目根不在 sys.path，报 No module named 'config'。运行时注入 $env:PYTHONPATH='.' 解决（未改代码）。
